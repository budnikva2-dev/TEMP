## 1. Подтверждённые баги (P0)

### 1.1. Хвост кометы не появляется НИКОГДА — ошибка единиц, строка 3770
```js
const rAU = b.position.distanceTo(starT.position) / AU_M;
```
`b.position` уже в а.е. (G=4π²), деление на `AU_M=1.496e11` даёт rAU≈2·10⁻¹¹. Guard `rAU > 0.02` не проходит → `I=0` всегда. Проверил: при r=0.45/3/10 а.е. I=0.000 во всех случаях. **Рецепт №10 «Комета» визуально сломан.** Фикс — одна строка:
```js
const rAU = b.position.distanceTo(starT.position); // уже а.е.
// после фикса: I(0.45)=1.0, I(3)=0.078, I(10)=0.013 — как и задумано «гаснет за ~7 а.е.»
```

### 1.2. Быстрый режим превращает эллипсы в окружности — `advanceOrbitsAnalytic` (1307–1324)
Код поворачивает вектор позиции вокруг оси момента на `n·dt`. Поворот **сохраняет длину** → радиус заморожен навсегда. Проверил комету a=3, e=0.85 из перигея:

| t | Код | Истинный Кеплер |
|---|---|---|
| 0.25 P | r=0.450 | r=4.579 |
| 0.5 P | r=0.450 | r=5.550 (афелий) |

Комета на ×10⁴+ вечно сидит в перигелии, планета **уходит с собственной орбитальной линии** (линия рисуется по кэшированным a,e). `jumpYears` наследует то же. Фикс — честное кеплеровское распространение по уже сохранённым `_orb` (a,e,p,q,h):
```js
function keplerDrift(b, dt) {
  const o = b._orb, mu = G * (getStar().mass + b.mass);
  const n = Math.sqrt(mu / o.a ** 3);
  const M = (b._M0 ?? Math.atan2(/* текущая истинная аномалия из r·p, r·q */)) + n * dt;
  let E = M;
  for (let i = 0; i < 7; i++) E -= (E - o.e * Math.sin(E) - M) / (1 - o.e * Math.cos(E));
  const xp = o.a * (Math.cos(E) - o.e), yp = o.a * Math.sqrt(1 - o.e * o.e) * Math.sin(E);
  const vp = Math.sqrt(mu * o.a) / (o.a * (1 - o.e * Math.cos(E))); // dE/dt
  // позиция = xp·p̂ + yp·q̂; скорость = -sinE·vp·p̂ + √(1-e²)cosE·vp·q̂ (+ star.position/velocity)
}
```
Храните `_M0` при `refreshElements` — и быстрые режимы станут точными для любых e.

### 1.3. В быстрых режимах и ⏩ коллизий нет вообще → красный гигант никого не съедает
`detectCollisions` вызывается только в ветке ≤×1000 (3693). `jumpYears` (3672–3683) и аналитика — без него. **Рецепт №7 «Смерть света» через ⏩ не работает**: Меркурий остаётся жить внутри звезды. Плюс справка обещает «съест Меркурий **и Венеру**», но R_RG=100 R☉=0.465 а.е., а перигей Венеры 0.715 — не достаёт никогда (проверил). Фикс:

```js
for (const b of state.bodies) if (!b.isStar && b.semiMajor * (1 - b.ecc) < Rstar)
```

### 1.4. Ядерная война × дискретизация ⏩: цивилизация не переживает перемотку
`CATASTROPHES` (514): период войны 1e3 лет. `jumpYears(1e9)` → 20000 шагов по **50 000 лет** → p=1−e⁻⁵⁰≈1 на каждом шаге. Комментарий 508–509 сам предупреждает («метастабильна… оставлено как есть») — я проверил, это хуже, чем метастабильность. **Монте-Карло 200 прогонов:**
- финальная стадия 4: **0 из 200**;
- ~**897** логов «Дайсон построен» и ~892 войны за одну перемотку → журнал (50 событий) целиком забит стробом;
- доля времени на стадии 4: 4.5%.

**Совет из справки «⏩ 1 млрд → дождаться цивилизации → Дайсон» математически невозможен.** Фикс — два уровня:
```js
// 1) жизнь тикает мелким шагом даже в перемотке (Пуассон уже корректен при любом dt):
const hLife = Math.min(h, 100);               // ≤ периода войны / 10
for (let t = 0; t < h; t += hLife) updateLife(hLife);
// 2) война — не чаще одного раза за эпоху цивилизации + шанс «отбиться» технологией:
{ name:'ядерная война', period: 1e5, drop: 1, oncePerEpoch: true, minStage: 4 }
```
И дедупликация логов: не писать «Дайсон построен» повторно, пока `kardashev` не менялся.

### 1.5. Все неводные биохимии застревают на стадии 2 навсегда
`computeEnvFitness` для стадии 2 (3564–3568) водно-центричен: `k_O2 = O2≥10 ? 1 : 0` и `|T−288|<30`. У титан-мира O2=0, T≈90 K → **fitness=0 → bioTime не растёт → стадия 3 недостижима**. Проверил численно: k=0.0. Справка обещает «метановой цивилизации нужно в 5 раз больше лет» — она не наступит никогда. `conditionsMet` уже хим-осведомлён (Ф48), а fitness — нет. Фикс:
```js
if (ls.stage === 2) {
  const c = BIOCHEMS[ls.chem || 'water'];
  const mid = (c.T[0] + c.T[1]) / 2;
  const k_clim = Math.exp(-((T - mid) / 40) ** 2);          // окно своей биохимии
  const k_solv = ls.chem === 'water' ? (b.atmO2 >= 10 ? 1 : 0.2)
             : (BIOCHEMS[ls.chem].need(b) ? 1 : 0.2);       // свой «кислород» — свой маркер
  return k_solv * (b.tectonics !== 'off' ? 1 : 0.5) * k_clim;
}
if (ls.stage >= 4) return /* та же формула, что для стадии 3 */;
```

### 1.6. Население не растёт: fitness стадии 4 = 0
`computeEnvFitness` заканчивается `return 0` (3576), а `updateLife` (3646–3647) множит рост на `fitP` → на стадии 4 коэффициент всегда 1. Фича З6 «рост ~6%/год» мертва. Фикс — ветка `stage>=4` выше.

### 1.7. Светимость: сброс, бинарная, эволюция, HZ-кольцо
Четыре связанных дефекта:
- `loadSolarSystem` (3862) сбрасывает `starType/starAge/starPhase`, но **не `state.starLum`**; ветки `empty`/`binary` в `loadPreset` — тоже. После TRAPPIST (L=0.000553) на паузе новые планеты «замёрзнут» до снятия паузы.

```js
state.starLum = state.bodies.filter(b => b.isStar).reduce((s, b) => s + (b.starLum || 1), 0);
// климат — сумма потоков всех звёзд:
const flux = state.bodies.filter(s => s.isStar)
  .reduce((f, s) => f + (s.starLum || 1) / Math.max(1e-6, b.position.distanceTo(s.position) ** 2), 0);
const T0 = T_SUN * Math.sqrt(R_SUN_M / (2 * AU_M)) * Math.pow(flux, 0.25);
// в updateThermodynamics при смене фазы или ΔL>5%: refreshHZRing();
```

## 3. Зрелость проекта

```js
// vite.config.js
import { viteSingleFile } from 'vite-plugin-singlefile';
export default { plugins: [viteSingleFile()] }; // three вендорится внутрь, файл работает offline
```
Дальше по убыванию ROI:
1. **Распил монолита без смены стека:** `core/physics.ts`, `core/climate.ts`, `core/bio.ts` (чистые функции, уже почти готовы — `stepNBody/greenhouseTau/updateLife` не трогают DOM), `render/`, `ui/`, `state/`. Vite + TS.
2. **Регрессионные тесты на уже верифицированных числах** — это ваш главный актив, закрепите его:
